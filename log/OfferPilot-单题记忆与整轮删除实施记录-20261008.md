# 单题记忆与整轮删除实施记录

## 问题对象
依据《OfferPilot-八股练习单题上下文与整轮删除设计-20261008.md》：Q-O1 整轮历史累积和重复压缩；Q-O2 回到旧题必须准确找到原始题答；Q-O3 删除后不能残留训练、索引或被迟到响应恢复；Q-O4 控制真实模型费用。

## 交付范围与完成标准
- Q-F1 / Q-A1：题目以会话 ID + 题目 ID 分组，每次提交立即持久化，最后一题和重启恢复同样可靠。
- Q-F2 / Q-A2：默认输入预算 30,000 token，受模型已知窗口、输出预留和安全余量约束。当前题为主；旧题只装载有界摘要和索引。
- Q-F3 / Q-A3：讨论题目与答题进度分离；可回到已开始的旧题并继续讨论，不能查看未来题解或错误推进当前题。
- Q-F4 / Q-A4：切题摘要直接从持久化事实生成，不调用模型；单题超长时按预算压缩，失败或无收益的相同来源不重复调用；原文不截断、不覆盖。
- Q-F5 / Q-A5：整轮删除在事务中物理删除全部会话数据，移除关联来源指针，取消在途请求，重复删除幂等，其他会话和共享题库保留。
- Q-F6 / Q-A6：以临时数据库和假模型验证正常与边界流程，不消耗付费 API，不改写冻结 benchmark 和旧采集结果。

## 实施记录
状态：已完成本轮实现及本地验收。实际生效代码是 Go 后端和 web 下的 React / TypeScript 前端；不修改未接入的根目录 src 实现。

后续每项记录注明对应 Q-F / Q-A、具体改动、验证命令和结果。离线测试不能据此宣称真实模型质量、费用或延迟提升。

### Q-F1 / Q-A1：持久化题目分组
- 新增 `question_memory.go`：稳定的会话 ID、题目 ID、题号、索引、消息 ID 目录、看答案状态、薄弱点与最近讨论原文片段。
- 题目组与原始消息、作答、评分、修订历史放在同一 SQLite 会话 JSON 聚合中，每轮保存时一起提交。不是把原文另存一份，也不是只有切题才保存；第十题同样保存。
- 旧记录读取时重建目录，正常保存时持久化；不改题目快照、原始文本或评分。新增分组字段可能令旧派生摘要的来源哈希失效，此时用原文重新组装，不把失效摘要作为事实。
- 验证：十题大历史、最后一题保存、重新打开数据库恢复全部原文；假模型调用数为零。

### Q-F2 / Q-A2、Q-F3 / Q-A3：30K组装与回看
- 默认输入预算改为30,000；实际预算仍取应用上限与“已知模型窗口－输出预留－安全余量”的较小值。更新示例配置及本地配置中的预算键，不展示密钥。
- 教学上下文先按讨论题筛选；已归档题只装载有界目录。评分继续使用本次完整作答和冻结依据，不读取其他题的作答来替代本次输入。
- 新增独立 `discussionOrdinal` 与 `focus` 接口；原 `current` 仍只由下一题推进。前端加入题目回看按钮、返回当前进度按钮，并只展示所选题对话。
- 支持明确的“回到第3题／回到第三题”；多题目标、未来题、外部索引拒绝。旧题回看用于教学追问；新的作答仍须回到当前题，旧提交可显式重评。
- 验证：回看第三题不改变第十题进度、追问绑定第三题、未来题不泄露、旧题讨论不能推进当前题。Next BFF实际转发 `questionId`，Go返回正确题号与策略版本。

### Q-F4 / Q-A4：压缩与预算边界
- 常规切题从已有事实生成简要记录，不调用摘要模型。目录过大时先精简内容；十题正常输入保留前九题索引，更多题目可用完整界面目录回查。
- 单题达到80%输入预算时，继续使用完整来源批次压缩；最近交流、本次原答、冻结依据、明确引用和用户约束优先保护。
- 摘要规定具体讨论点、未解决疑问、结论和纠正；最多2,000字、3项引用、每项200字，输出字节上限128KiB。无效输出不能进入上下文。
- 加入来源内容哈希＋模型＋策略缓存：相同无收益批次不再调用；失败批次冷却10分钟；缓存最多128项。来源变化产生新键，持久化缓存随整轮删除一起清理。
- 先计算必须保留的输入，再分配目录、摘要和关键词回查空间；不因可选摘要堆积而拒绝能放下的原答。超过预算的必需原文仍明确报错并保留全文，不假装能够无限装载。
- 验证：长单题成功压缩、来源原文哈希不变、压缩后原文可明确引用；同一无收益输入连续两次构建不增加模型调用；接近上限时可选摘要不会挤出原答；超长必需输入不截断。

### Q-F5 / Q-A5：整轮物理删除
- `DeleteTrainingConversation` 在事务中检查档案与版本，物理删除会话聚合，因此该轮题目组、原文、评分修订、摘要、索引、运行记录和压缩缓存同时消失。
- 独立创建的复测保留，但在同一事务里解除对已删来源的指针。新复测插入时用单条SQL检查来源存在，防止检查后来源被删除的竞态。
- 删除成功后取消本会话在途生成、评分和复测请求。迟到保存只允许更新已有正确版本，不能重新插入被删会话。重复删除成功；已存在记录的旧版本删除返回冲突。
- 前端删除期间中断请求，并以请求序号拒绝迟到响应；清理草稿、引用、片段、工作消息和活动会话ID。其他标签页通过临时广播清理相同会话，不新增永久删除标记。
- 能力统计、训练历史从剩余数据库记录重新投影；本场贡献随删除移除。共享知识库和其他会话保留。
- 验证：数据库行不存在，历史／统计／原文回查同时消失；重复删除、旧版本冲突、在途生成／评分、迟到回调、新复测竞态、独立复测指针解除。另验证反复创建删除时SQLite空闲页可复用，主库不因同尺寸记录无限增长；无需每次删除执行VACUUM。

### Q-F6 / Q-A6：验证留档与未声称的结果
- 新证据目录：`验证结果/question-memory-20261008/`。使用临时SQLite与本地固定模型；不读写用户训练数据来做测试。
- 保留原冻结输入、旧版本采集和中断采集证据。原web软删除集成脚本留存，新建 `question-memory-bff-smoke.mjs` 验证新删除语义，避免将旧保留训练语义混作新验收标准。
- 首次回归发现普通聊天受到练习摘要配额影响，随后将配额限定到练习，39条冻结合同检查恢复通过；冻结断言没有改写。原单元测试中“旧题必须调用摘要模型”改为“旧题归档不调用模型”，对应已批准的Q-F4。
- 初次集成命令使用错误相对路径而未启动测试进程；改用绝对路径后18项实际BFF链路检查通过。
- 后续最终验证和运行状态记录在下节。真实模型质量、费用、延迟提升百分比仍须独立限额采集；本轮没有启动该采集，也不承诺浏览器手动交互已验证。
